# SiteProof 利用ガイド（実用版 RC1）

自分が管理するWebサイトを、画像の変化で監視するためのガイドです。実際に動く機能だけを書いています。できないこと・未検証のことは最後の「制限と既知の問題」にまとめました。

## 1. 何ができるか（目的）

- 登録した自分のサイトのトップページを、定期的に撮影し、**承認済みの基準画像（Baseline）** と比べて、見た目の変化を知らせます。
- 判定は「変更なし／変更あり／判定不能」の3つです。**品質が合格かどうかは判定しません**（総合品質は常に UNKNOWN）。
- AWSで動かしたHTTP監視（死活）の保存結果を取り込んで、同じ画面（HOME）で見られます（取り込みは任意）。

## 2. 必要なもの（Windows）

| もの | 用途 |
|---|---|
| Windows 11 | 動作確認した環境です |
| Python 3.15 | アプリ本体（標準ライブラリのみ。3.12より前は動きません。3.12〜3.14は未検証） |
| Webブラウザ（Firefox・Edge・Chrome） | 画面の表示（Firefox 160で確認） |
| Docker Desktop と、固定した撮影イメージ | **実サイトの撮影にだけ必要**です。表示の確認や合成デモには不要です。撮影イメージの確認と準備の状況は [REAL_CAPTURE.md](REAL_CAPTURE.md) の「撮影イメージの準備」です（固定イメージを別のPCで用意する方法は、まだ確立していません） |
| OpenSSH（`ssh-keygen`。Windows 11に標準） | 監視許可の署名・検証 |
| 自分の鍵（ssh-ed25519） | 監視許可に署名します。SiteProofは鍵を持ちません |

AWSのアカウントや認証は、アプリの利用には不要です。

## 3. インストールと起動

```powershell
git clone <このリポジトリ>
cd siteproof
SiteProof.cmd              # ダブルクリックでも可。または: py -3.15 -B -m src.noxiworks.app
```

`http://127.0.0.1:8765/` がブラウザで開きます（開かないときはこのURLを入力）。すでに起動中なら、画面を開くだけです。

## 4. サイトの登録と所有権の確認

1. HOMEの **「サイトを追加」** で、サイト名・ページのURL（https の公開ホスト名・トップページ）・画面サイズ（Desktop／Mobile）を入力し、「このサイトは自分が管理しています」にチェックして **「登録して監視を始める」** を押します。登録するのはサイトの最初のページで、サイトは複数（20まで）登録できます。同じサイトのページは、登録後に画面の「ページを追加」で最大5ページ（最初のページを含む）まで追加できます（追加したページはHTTP監視だけが使えます。画像の撮影はトップページ（/）だけです）。
2. 登録しただけでは、**実サイトには一切アクセスしません**。HOMEの「実サイト監視の準備」に、足りない条件が一覧で出ます（所有権の確認・署名付き監視許可・撮影構成の一致・Docker・撮影ハーネス）。
3. **所有権の確認**：次の2つに対応しています。
   - **DNSのTXTレコード（どのサイトでも可・独自ドメインも可）**：サイトの画面の **「所有権の確認」** で確認用のTXTレコードを発行し、自分のDNSに登録してから「確認」します。確認にはDNSの照会が必要なため、**照会は現在無効にしてあります**（`tools/dns_ownership.py` の `OWNERSHIP_DNS_ENABLED = False`。有効化にはあなたの承認が必要です）。それまでは、レコードの発行まではできますが、確認済みにはなりません。
   - **`workers.dev` のサイト**：Cloudflareのアカウントで確認します（自動）。
   確認用ファイルを置く方法と、TXTレコードの自己申告には対応していません（画面では選べず、セットアップツールも拒否します）。確認が済むまで、実サイトの撮影・検査は始まりません（登録はできます）。詳しくは [REAL_CAPTURE.md](REAL_CAPTURE.md) の「所有権の確認方法」です。

## 5. 監視許可（Permit）の設定

SiteProofが実サイトを撮影してよいのは、**利用者が自分の鍵で署名した監視許可**が、登録したサイト・対象ファイル・期間・回数・撮影構成と一致するときだけです。

1. 自分の公開鍵を `<データ>\trust\allowed_signers` に置きます（書式は [REAL_CAPTURE.md](REAL_CAPTURE.md)。SiteProofは書き込みません）。
2. HOMEの「実サイト監視の準備」で **初回セットアップを開始** を押します。別のウィンドウが開き、許可の内容が表示されるので、確認して `y` を入力し、鍵のパスフレーズで署名します（鍵・パスフレーズはアプリを通りません）。
3. 画面を更新すると「署名付き許可」の項目が「対応」になります。許可には**期限と回数**があり、残り7日以下または5回以下で警告が出ます。更新は **「監視設定を更新」** で行います（Baselineは引き継がれます）。
4. 許可の発行は **SiteProofではできません**。HOMEのボタンは、利用者のウィンドウでセットアップを起動するだけです。

コマンドで行う場合は [REAL_CAPTURE.md](REAL_CAPTURE.md) の「使い方」を参照してください。最初の実撮影を1回だけ試したいときは、`tools/setup_monitoring.py` に `--max-runs 1 --manual-only` を付けると、許可が1回限りになり、自動監視も始まりません（撮影は「今すぐ再検査」で行います）。

## 6. Baselineの作成・承認・更新

| 段階 | 何が起きるか | あなたの操作 |
|---|---|---|
| 作成（自動） | 初回の検査で Desktop・Mobile とも「撮影が完了し、安定していた」ときだけ、初期Baselineを自動作成します（「自動作成（未確認）」）。不安定・失敗のときは作らず、次の検査で再試行します | なし |
| 承認 | 差分レビューで画像を見て、**「初回Baselineを承認する」** を押すと、正式な承認記録が残ります | あなた |
| 更新 | 変更を検知したら、変更後の画像を差分レビューで確認し、**「新しい基準にする」** を押すと、Baselineが v+1 になります（古い版は残ります） | あなた |

- Baselineは、検査や予定から**自動では書き換わりません**。承認・更新は、画面でチェックを入れて押したときだけです。
- 撮影が不安定・失敗した画像は、Baselineにできません。

## 7. 監視の開始・停止

- HOMEの **「監視を開始」** で定期検査が始まります。**「監視を停止」** で止まります。停止したものは、**自動では再開しません**。
- 検査間隔は、補助操作（その他の設定）で 15分・1時間・6時間・24時間 から選べます（既定は1時間）。「今すぐ再検査」もあります。
- HOMEの一番上に、①監視が動いているか、②問題があるか、③最後に検査した時刻、④あなたが次にすることが表示されます。
- 許可の回数を使い切ったり期限が切れたりすると、撮影せずに止まり、「開始できない理由」を表示します。

## 7.5 HTTP監視（サイトの死活）と通知

HOME・ACTIVITY・DETAILの **「HTTP監視」** に、状態（正常・障害・判定不能・未監視・長期間未観測・停止中）、最新のHTTPステータス、応答時間、TLS証明書の期限、最終観測、次回予定、障害・復旧の履歴、通知が出ます。画像監視とは別の監視です（間隔は5分・15分・30分・1時間から選びます）。**現在は外部通信を無効にしてあり、実際の確認は行いません**（検査の隔離は、外部ネットワークのない模擬環境で18項目すべて実測済みです。実サイトでの試験と、あなたの承認が済むまで無効のままです）。サイトが接続に応答しない・拒否するときは「障害」、検査の仕組みの異常や証拠の不足は「判定不能」と表示します。方式・安全条件・有効にする手順は [HTTP_MONITORING.md](HTTP_MONITORING.md) です。「今すぐ検査」も、許可された回数と間隔の中で1回と数えます。

## 7.6 複数サイト

サイトを2つ以上登録すると、HOME（`/`）は **「全サイトの状態」** の一覧になります。確認が必要なサイトが上に並び、サイトごとに画像監視・HTTP監視を個別に停止・開始できます。「このサイトを開く」で、そのサイトだけの画面（`/site/<site id>/`）に移ります。設定・許可・Baseline・履歴・通知はサイトごとに分かれ、混ざりません。1サイトだけのときの画面は従来どおりです（データの移行は不要です）。サイトが複数あるとき、コマンドのツールは `--site <site id>` が必要です。

## 7.7 メール通知

**現在は送信を無効にしてあります。** 有効にするには、(1) Windowsの資格情報マネージャーへの登録、(2) `tools/notify_grant.py` での署名、(3) 承認のうえでの外部送信の有効化、(4) 画面の「全サイト共通」と「このサイト」のスイッチ、が必要です。手順と保証の範囲は [NOTIFICATIONS.md](NOTIFICATIONS.md) です。「送信受付済み」は受信の保証ではありません。

## 7.8 保存容量・整理・バックアップ

サイトの画面の **「保存容量・整理・バックアップ」** で、使用量の確認、HTTP履歴・通知履歴の整理（別ファイルへの移動。削除はしません）、バックアップ（データフォルダの隣の新しいフォルダへ写して照合）ができます。復元は手動で、**新しいフォルダ**へコピーします。

## 7.9 はじめの手順・導入環境・復元

HOMEの **「はじめの手順」** が、次にすることを実際の状態から示します。**「導入環境の確認」** では、Python・Docker・固定イメージ・データフォルダなどの不足を確認できます。導入・復元・更新・停止・アンインストールは [INSTALL.md](INSTALL.md) です。

## 8. AWSの保存結果の取り込み（任意）

AWS-B（HTTP監視）の結果を、自分で保存してからローカルに取り込めます。取り込みはローカルの処理だけで、**SiteProofがAWSに接続することはありません**。

```powershell
py -3.15 -B -m src.noxiworks.archive import-export --archive <データ>\sites\<site-id>\aws-archive `
  --targets <データ>\sites\<site-id>\targets.json --capture-plan <データ>\sites\<site-id>\capture_plan.json export\e1
```

`export\e1` は、自分で保存した `aws dynamodb` の出力フォルダです（手順は [RUNBOOK_AWS_B_LITE.md](aws_portfolio/RUNBOOK_AWS_B_LITE.md) §9.1）。取り込んだページは、署名済みの `targets.json` を書き換えずにHOMEに表示されます。

- 取り込んだ結果は、時間が経つと **STALE（古い）** と表示します。古い「正常」を今の正常として扱いません。取り込み前は「未取得」です。
- **AWS-B Liteは期限つきのTrial（停止期限 2026-11-27 12:00 JST）** です。ずっと動くクラウドサービスではありません。期限後は、保存済みの結果だけが残ります。

## 9. アプリを閉じている間の監視（バックグラウンド）

- 既定では、**アプリを開いている間だけ**監視します。
- 閉じている間も監視したいときは、HOMEの **「アプリを閉じても監視する」** を押します（Windowsのタスク スケジューラに登録。15分ごとに「予定の検査があれば1回」実行）。**解除する** で外せます。登録は自動では行いません。
- 登録しても、停止中の監視は動きません。許可が切れれば撮影しません。
- 詳細・注意は [BACKGROUND_MONITORING.md](BACKGROUND_MONITORING.md)。2026-11-26に、本人管理サイト1件で、画像のタスクによる予定の撮影とHTTPのタスクによる検査、解除までを実環境で確認しました。

## 10. データの保存場所

既定は `%LOCALAPPDATA%\SiteProof`（`--data <フォルダ>` で変更）。

| 場所 | 内容 |
|---|---|
| `sites\<site-id>\` | 登録したサイトの全データ（`site.json`・`targets.json`・`capture_plan.json`・`monitor.json`・`monitor-log.jsonl`） |
| `sites\<site-id>\runs\` | 検査ごとの撮影画像と証拠（SHA-256つき。削除しません） |
| `sites\<site-id>\registry\` | Baselineの版と承認記録 |
| `sites\<site-id>\real\` | 署名付き監視許可（`permit.json` と `permit.json.sig`）・所有権の確認記録 |
| `sites\<site-id>\aws-archive\` | 取り込んだAWSの保存結果 |
| `trust\allowed_signers` | あなたが置く、署名を信頼する公開鍵 |
| `background\` | バックグラウンド監視のログ（`<site id>-image.log`・`<site id>-http.log`） |

撮影画像や許可には、サイトの情報が含まれます。**共有・公開しないでください。** 保存容量は、サイトごとの上限（既定2GB）の80%で警告し、上限で監視を一時停止します。

## 11. 安全な終了

1. 実行中の検査があれば、終わるのを待ちます（HOMEが「検査中」でなくなります）。
2. 必要なら **「監視を停止」** を押します。
3. アプリを起動したターミナルで `Ctrl+C`（または `SiteProof.cmd` のウィンドウを閉じる）。
4. 再起動すると、設定・Baseline・履歴はそのまま引き継がれます。バックグラウンド監視を登録している場合は、アプリを終了しても動き続けます（止めるなら **解除する**）。

## 12. 制限と既知の問題

- **品質は UNKNOWN のまま**です。撮影プロファイルは未認証（PROFILE_UNATTESTED）で、「変更あり」は画像に差があるという意味にすぎません。
- **外部リソース（外部の天気・地図など）が遮断されたページは、比較が「判定不能」になります**（仕様どおり。比較の判定を PASS にはしません）。この場合も、撮影が完了して安定していれば、Baselineとして承認できますが、品質は未確認のままです。外部リソースの遮断を理由にBaselineの承認条件を緩める機能はありません（MVPの対象外）。
- 実サイトの撮影・HTTP監視・バックグラウンドのタスクは、作者の本人管理サイト（workers.dev）で通しの確認をしました（2026-11-26）。**一般のサイトでの撮影・隔離は未検証**です。
- 実撮影の許可は、検査間隔を含む対象設定（`targets.json`）を固定します。**署名の後に画面で画像監視の間隔を変えると、撮影が止まります**（署名し直しが必要）。
- 以前の許可を外してから新しい許可に署名すると、以前のBaselineは引き継がれず、撮影が止まります（安全側）。更新は、以前の許可を残したまま「監視設定を更新」で行ってください。
- 1サイトにつき最大5ページ（追加したページの画像撮影は未対応）。サイトの変更・削除は未対応です。メールの送信は無効に戻してあります（2026-11-27に、Gmailでテスト通知1通の送信と受信を確認済み。日常の利用は、通知の許可に署名し、外部通信のスイッチを有効にしてから）。
- このPCからのHTTP監視は、外部通信のスイッチを無効に戻してあります（隔離は模擬環境で18/18、本人管理サイトで限定試験4回を実測済み。常時の運用はUSERの承認とHTTPの許可の署名の後）。HTTPSのIPv4だけで、転送先は確認しません。独自ドメインのサイトはDNSのTXTレコードで所有権を確認できますが、DNSの照会は無効のままです（実DNSでは未検証）。AWSの料金はUNKNOWNです。
- 撮影ごとに、証拠のDocker volumeが1つ残ります（SiteProofは削除しません）。macOSの例は未確認です。
- 独立Stopperは未適用で、AWS-Bの停止の確認・資源の削除は手動です。

## 13. 日常の運用

| いつ | すること |
|---|---|
| 毎日（任意） | HOMEの一番上で、監視が動いているか・問題があるか・次にすることを確認します。「判定不能」「障害」は、差分レビュー・履歴で理由を見ます |
| 変更を検知したとき | 差分レビューで画像を確認し、意図した変更なら **「新しい基準にする」**。意図しない変更なら、サイトを確認します |
| 許可の期限・回数の警告（残り7日／5回） | 画像は **「監視設定を更新」**（`tools/setup_monitoring.py`）、HTTPは `tools/http_grant.py` で署名し直します。Baselineは引き継がれます |
| 週に1回（推奨） | 「保存容量・整理・バックアップ」で **全データをバックアップ**（照合つき）。使用量が80%を超えたら「履歴を整理」 |
| Windowsの再起動・Docker Desktopの更新の後 | Docker Desktopを起動します（HTTP監視と撮影に必要。SiteProofはHTTP監視のためにDockerを起動しません） |
| プログラムを更新するとき | 監視を停止 → `tools/pre_update.py`（照合つきバックアップ）→ 入れ替え → `tools/doctor.py`。撮影構成のファイルが変わる更新では、画像の許可の署名し直しが必要です（[INSTALL.md](INSTALL.md)） |
| しばらく使わないとき | 「このサイトの監視をすべて停止」と、バックグラウンドのタスクの「解除」 |

困ったとき：画面の「導入環境の確認」（または `tools/doctor.py`）で、足りないものと次にすることが分かります。止まった理由は、各監視のパネルに日本語で表示されます。
