## 費用が想定を超える経路

| 経路 | 対策(実装済みのもの) | 残る穴 |
|---|---|---|
| Lambdaの暴走・再試行 | 予約同時実行数1、再試行0、イベント寿命60秒、絶対期限、タイムアウト20秒 | 予約同時実行を確保できないアカウントでは無効化される |
| インスタンスの停止漏れ | OSタイマー、Watchdog(期限＋周期)、欠測Alarm | 3層とも失敗し人も不在の場合 |
| T3のクレジット超過 | `CPUCredits=standard` | — |
| CloudFrontへの大量アクセス | Alarm(通知のみ) | 通知から人が止めるまでの間は課金される |
| ログの無期限保存 | ロググループをIaCで作成し保持日数を明示 | — |
| 残余資源の放置 | Runbookの棚卸し手順、`Project` タグ | タグの付かない資源、Retain資源 |
| NAT Gateway等の高額資源 | テンプレートに存在しない(契約テストでVPC接続を禁止) | — |

## 測定計画(LIVE時)

1. `Project` / `Component` をコスト配分タグとして有効化する(反映に時間がかかる)。
2. 各段階の開始前後でCost Explorerの日次をCSV保存する。
3. 見積との差を項目別に記録する。反映遅延中は「未確定」とする。
4. 撤収後、数日あけて再確認する。
