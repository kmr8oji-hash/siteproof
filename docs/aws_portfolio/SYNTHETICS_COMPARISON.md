# AWS-B Lite と CloudWatch Synthetics の費用・機能比較

**費用はすべて推定（計算値）です。実請求ではありません。** SiteProofの運用ユーザーには請求情報を見る権限がなく、AWSの実請求額は **UNKNOWN** です。AWS-B Liteの6時間・12時間間隔は **LIVE未検証**（Stage Aの実測は15分間隔）です。

「Syntheticsより安い」とは、**下の条件を満たすときだけ**言えます。Syntheticsのほうが有利な条件もあります。

## 前提（すべての表で共通）

- リージョン us-east-1、監視対象 **5ページ・3サイト**、**HTTP監視**（ページ到達と応答コードの確認）、**6時間間隔**（1ページ 120回/月）、**30日間**、無料枠・クレジット・税なし。
- 単価：AWS公式の公開価格データ（Amazon CloudWatch、us-east-1、公開日 2026-11-19、取得日 2026-11-22）。
  - Synthetics：**$0.0012 / Canary実行1回**
  - カスタムメトリクス：**$0.30 / 1メトリクス・月**（最初の1万個まで）
  - 標準Alarm：**$0.10 / 1本・月**
- **算入範囲を2つに分け、混ぜません。**
  - **CloudWatch課金分**：Canary実行料金、カスタムメトリクス、標準Alarm。上の公式単価から計算でき、全構成で同じ範囲です。
  - **他サービス**：Lambda、DynamoDB、SNS、Scheduler、S3、CloudWatch Logsなど。Lite・従来AWS-Bは既存の推定値（約0.01）があります。**Syntheticsは、Canaryの実行環境（Lambda）、成果物のS3保存、Logs、Canaryが自動で出すメトリクスの課金有無のいずれも未確認で、UNKNOWNです。**推測で埋めていません。
- このため、Syntheticsの合計は**「CloudWatch課金分のみ」で、実際より小さい下限寄りの値**です。Syntheticsに有利な比較になっています。

## 比較する構成と、通知の粒度

| 構成 | 内容 | 通知の粒度 |
|---|---|---|
| 従来AWS-B | ページ別にAlarm 3本・カスタムメトリクス4個（5ページで Alarm 15本・メトリクス 20個） | ページ別（失敗・判定不能・保存失敗の3種） |
| **AWS-B Lite** | Lambdaがページ別に状態変化を判定してSNSへ直接通知。集約Heartbeat（メトリクス1個＋Alarm 1本） | ページ別の状態遷移（障害・復旧・判定不能）＋全体のHeartbeat欠測 |
| Synthetics A：1ページ1Canary ＋ページ別Alarm | 5 Canary、成功率のAlarm 5本 | ページ別（Alarmの状態） |
| Synthetics B：サイト単位Canary ＋サイト別Alarm | **3 Canary**（3サイトに1つずつ。各Canaryがそのサイトのページを1回の実行で順に確認）、Alarm 3本 | **サイト単位**。どのページが失敗したかは、実行の結果を見て確認 |

## 表1：CloudWatch課金分の月額（通知まで含む構成、USD）

| 構成 | 計算 | 月額（CloudWatch課金分） |
|---|---|---:|
| 従来AWS-B | Alarm 15×0.10 ＋ メトリクス 20×0.30（**按分なしの上限**） | **7.50** |
| **AWS-B Lite** | メトリクス 0.30（**上限**）＋ Alarm 0.10 | **0.40** |
| Synthetics A（5 Canary＋Alarm 5本） | 5×120×0.0012 ＝ 0.72、＋ 5×0.10 ＝ 0.50 | **1.22** |
| Synthetics B（3 Canary＋Alarm 3本） | 3×120×0.0012 ＝ 0.432、＋ 3×0.10 ＝ 0.30 | **0.73** |

- 他サービス（Lambda等）：Lite・従来AWS-Bは約0.01（既存の推定）。したがって、**Lite全体は約0.41**です（下の「0.41の前提」）。Syntheticsは **UNKNOWN**。
- 同じ粒度（ページ別の通知）で比べると、Lite 0.40 対 Synthetics A 1.22 で、Liteは約1/3です。サイト単位のSynthetics Bと比べても、Liteが小さい（0.40 対 0.73）。ただしBは通知の粒度が粗い（サイト単位）構成です。
- 従来AWS-Bの7.50は、メトリクスを月全体で課金する上限です。**時間按分が成立する場合**（データのある時間帯だけ課金される、6時間間隔で1日4時間分とする）は、メトリクスが 20×0.30×4/24 ＝ 1.00 になり、合計は **2.50** です。按分の成否は未確認です。同じ前提をLiteに当てると、メトリクス 0.05 ＋ Alarm 0.10 ＝ **0.15**（全体で約0.16）で、これは参考値です。

## 表2：Syntheticsの実行料金のみ（Alarm・通知なし。表1とは別の範囲、USD）

| 構成 | 計算 | 月額（実行料金のみ） |
|---|---|---:|
| Synthetics A（5 Canary） | 5×120×0.0012 | 0.72 |
| Synthetics B（3 Canary） | 3×120×0.0012 | 0.43 |

これは**固定費（Alarm）を含まない**値で、通知を出すための構成ではありません（結果をコンソールで見るだけの使い方）。**表1の総額と並べて比較しません。** Liteには、実行回数に比例する小さな分（Lambda等、約0.006）以外の変動費がなく、Lite側にこれに当たる欄はありません。

## 検査の頻度による変化（表1と同じ範囲：CloudWatch課金分、通知付き）

| 間隔 | Canary1つあたりの実行/月 | Synthetics A（5 Canary＋Alarm 5） | Synthetics B（3 Canary＋Alarm 3） | AWS-B Lite（全体の概算） |
|---|---:|---:|---:|---:|
| 24時間 | 30 | 0.68 | 0.41 | 約 0.40 |
| 12時間 | 60 | 0.86 | 0.52 | 約 0.41 |
| 6時間 | 120 | 1.22 | 0.73 | 約 0.41 |
| 1時間 | 720 | 4.82 | 2.89 | 約 0.44 |
| 15分 | 2,880 | 17.78 | 10.67 | 約 0.55 |

Liteの固定費（メトリクス＋Alarm）は0.40で、検査回数に応じて増えるのはLambda等の小さな分だけです（既存の試算の1回あたりの値を比例で伸ばした概算。DynamoDB等の伸びは小さいとして含めていません）。Syntheticsは**実行回数に比例**して増えます。

- 通知付きの構成どうしで比べると、**ページ別通知のSynthetics Aは、表の全範囲でLiteより高い**。
- サイト単位のSynthetics Bは、**約24時間間隔でLiteとほぼ同額**になります。それより間隔が長ければSyntheticsのほうが安くなりえます。
- Syntheticsの他サービス費用はUNKNOWNで、上の値には含みません。含めればSyntheticsはさらに高くなります。

## 機能の違い（AWS公式の一般的な説明に基づく。本環境ではSyntheticsを試していません）

| 観点 | AWS-B Lite | CloudWatch Synthetics |
|---|---|---|
| 検査の内容 | HTTP GETの応答（状態コード、TLS期限など）。ブラウザは使わない | スクリプトによるブラウザ操作・APIの検査、スクリーンショット、複数ステップの確認など、**はるかに豊富** |
| 運用の手間 | 自作のコードとテンプレートを自分で保守する | **マネージド**。保守・拡張・サポートはAWS側 |
| 通知 | ページ別の状態変化（Lambdaが直接送信）。重複は起こりうる（完全なExactly Onceではない） | CloudWatch Alarm経由 |
| 停止の制御 | 絶対期限・世代・同時実行0などで止める設計。**独立Stopperは未適用**で、完全な自律停止は未完成 | 通常の停止・削除操作 |
| 実証の範囲 | 1実ページ＋fixtureの限定試験（Stage A）。6h/12hは未検証 | 本環境では未試験 |

**機能の数でSyntheticsを上回るとは主張しません。** 一般的なWeb監視をそのまま運用するなら、Syntheticsは妥当な選択肢です。

## Syntheticsより安いと言える条件／Syntheticsが有利な条件

- **Liteが安い**：**ページ別の通知**が必要で、検査の間隔が24時間より短い場合（表の範囲では、ページ別通知のSyntheticsより常に安い）。HTTPの応答確認で足りる場合。間隔が短いほど、ページ数が多いほど差が広がります。
- **Syntheticsが有利**：
  - 間隔が約24時間以上で、サイト単位の通知で足りる場合（Synthetics Bのほうが安くなりえます）。
  - **通知を必要とせず**、結果をコンソールで見るだけなら、実行料金のみ（0.22〜0.72）で、Liteの約0.41より安くなりうる構成があります（表2）。
  - ブラウザ操作・画面の確認・マネージドの運用や保守のなさを重視する場合。費用以外の価値は、本書の表に入っていません。

## SiteProofの位置づけ（差別化）

SiteProofの狙いは、Syntheticsの代わりになることではなく、**自分の管理するサイトを少ない費用で見守る**ための次の組み合わせです。

1. **AWS構成の低コスト化**：ページ別のAlarmとメトリクスを、集約Heartbeat 1本に置き換える。
2. **ページ別の状態変化通知**：障害・復旧・判定不能の遷移だけを通知し、同じ状態を繰り返し送らない。
3. **集約Heartbeat**：監視が静かに止まった（実行されない、保存できない、通知できない）ことを、欠測として検知する。
4. **安全な停止制御**：絶対期限、世代、条件付き確保、同時実行0。停止後や古いイベントは接続前に拒否する。
5. **ローカル画像検査との統合**：HTTPの結果と、画面の見た目の変化（Baseline比較）を、同じ画面で確認する。
6. **日本語のダッシュボード**：6画面のローカルアプリ。
