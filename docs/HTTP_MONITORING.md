# HTTP監視（サイトの死活）と通知

登録したサイトのHTTPS到達・ステータス・応答時間・TLS証明書の期限を、このPCで定期的に確認します。**画像監視とは別の監視**（別の間隔・別の許可・別の停止）です。

> **現在の状態（2026-11-26）：実装済み・オフライン検証済み・隔離fixtureで18/18 PASS・本人管理サイト（workers.dev）で限定試験4回を実測（2026-11-26・すべて HTTP 200・隔離違反なし。RELEASE_CANDIDATE.md 5.2）。外部通信は無効に戻してあります。**
> `src/noxiworks/http_monitor.py` の `HTTP_EXTERNAL_ENABLED` は `False` です。安全境界の実測とUSERの承認が済むまで、実サイトへの要求は1回も送られません（テストは差し込んだ偽の応答だけで動きます）。

## 方式の選定（既存のProbeを再利用）

| 候補 | 評価 |
|---|---|
| **AWS-B Probe の再利用（採用）** | `src/aws_b/probe.py` は、許可ホスト1件・DNS回答の全件検証・承認済みIP1つへの1回の接続・接続先の照合・リダイレクト非追従・再試行なし・証明書/ホスト名検証・先頭行のみ読む・期限、をすでに備え、既存テストがあります。ローカル用には設定オブジェクト（ホスト・パス）を渡すだけで、通信の安全部分を作り直しません。 |
| Uptime Kuma | HTTP・TLS期限・通知は揃うが、別のWebアプリ＋別のDB＋Docker（イメージ取得）が要り、接続先の固定（ピン留め・私設IP/メタデータ拒否）をこちらの規則にできない。SiteProofの画面とも別になる。**導入にはイメージ取得が必要なため、今回は実行していません。** |
| Gatus | 設定ファイル1つで軽く、証明書期限・通知も標準。ただし接続先のピン留めはできず、画面も別。導入にはバイナリ/イメージの取得が必要で、今回は実行していません。 |

KumaとGatusの評価は、一般的な機能の理解に基づくもので、このスプリントで導入・実測したものではありません。以前の方針（AWS先行・Kuma/Gatus/Dockerに戻らない）とも合っています。外部サービスを足さず、既存の安全部分を使うのが最小です。

## 何を確認するか

HTTPS到達 / HTTPステータス / 応答時間 / TLS証明書の期限（残り日数） / 障害理由 / 検査時刻 / 次回予定。履歴は `http-history.jsonl`（追記のみ）、設定は `http-monitor.json`。間隔は **5分・15分・30分・1時間**（画像監視の間隔とは独立。既定は15分）。

## 状態（前回の結果だけで「正常」と表示しない）

| 状態 | 意味 |
|---|---|
| 正常 / 障害 / 判定不能 | 直近の観測（間隔の2倍以内）の結果 |
| 未監視 | まだ開始していない、または開始後まだ観測がない |
| 長期間未観測 | 最後の観測が間隔の2倍より古い。**最後の結果は参考表示で、現在の状態としては出さない** |
| 停止中 | 利用者が停止した。最後の観測は「停止前の最後の観測」と明示 |

3xx は判定不能（追従しない）、通信できない・TLS失敗は障害、応答が読めない・拒否された接続先は判定不能です。AWS-Bの保存結果は別の画面のままで、ここには混ぜません（ここに出るのは、このPCの観測だけ）。

## 安全条件

条件ごとの成立状況・残る制限・実測計画は [HTTP_BOUNDARY.md](HTTP_BOUNDARY.md) にまとめています。

- 許可は **画像撮影の許可と別**です。`tools/http_grant.py` が、サイト・ホスト1件・パス・期間・最短の間隔・総回数・所有権の証拠を、利用者の鍵（OpenSSHの署名）で署名します。形式は `siteproof.http-grant.v2`（回数と所有権を含まない v1 は使えません）。署名しても監視は始まらず、外部通信も有効になりません。
- 検査は1回ごとに、**隔離コンテナを1つ起動して1回だけ**行います（`src/noxiworks/http_isolation.py`。撮影と同じ通信制御・Grant Broker・reaperを使い、コンテナの中のWorkerが許可された1つのIPの443番へ1回だけ接続します）。実行の直前に、署名・対象・期間・所有権・回数を**もう一度確認**し、台帳（`trust/http-ledger/`）に1回分を記録してから要求します。**Docker Desktopが起動している必要があり、HTTP監視のためにDockerを起動することはありません**。起動していないときは検査せず、画面に「未検査」（理由と時刻）を出します（「正常」とは表示しません）。
- **手動検査も同じ許可・同じ間隔・同じ回数**で数えます。許可を更新しても、直前の検査からの間隔は守ります。
- アプリとWindowsタスクの同時実行は、OSのファイルロックで防ぎます。停止の操作が、実行中の検査の保存に上書きされることはありません。
- HTTPSのみ（443）、リダイレクト拒否、DNS回答の全件検証と実接続先の一致、私設IP・メタデータ等の拒否、証明書とホスト名の検証、先頭行のみ・16KiB上限、名前解決3秒・接続5秒（Proxy）・全体8秒、**再試行なし**、IPv6は使いません。
- コンテナの境界（通信の遮断・許可した1つのIPだけを通すこと）は、**外部ネットワークのない模擬環境（隔離fixture）で18項目すべて実測済み**です。また本人管理サイト（workers.dev）で限定試験4回を実測（2026-11-26・すべて HTTP 200・隔離違反なし。RELEASE_CANDIDATE.md 5.2）。実サイトでの限定試験は [HTTP_BOUNDARY.md](HTTP_BOUNDARY.md) のM3で、USERの承認のうえで行います。
- 相手が接続に応答しない（時間切れ）・接続を拒否するときは**障害**（`CONNECT_TIMEOUT`／`CONNECT_FAILED`）です。隔離の仕組み（Broker・Proxy・規則）の異常や証拠の不足は、**判定不能**です。
- 開始は初期状態で無効。画像監視の停止・開始とは連動しません。PCが止まっていた間の検査は、あとからまとめて実行しません（未観測の期間として残ります）。

## 通知

- アプリ内通知（HOME・ACTIVITY・DETAILの「通知」）は常に記録します。メールは、別の許可と明示的な有効化があるときだけ送ります（[NOTIFICATIONS.md](NOTIFICATIONS.md)。実装済み・模擬送信で検証済み、**実際の送信は無効**）。Webhookは未実装です。
- 通知する：サイト障害 / 復旧 / 判定不能 / TLS証明書の期限（14日・3日・期限切れ。証明書ごと・段階ごとに1回） / 画像の変更検知・判定不能・失敗（その結果になった**最初の1回**）。
- **同じ異常が続く間は、通知を繰り返しません**（状態が変わったときだけ）。同じ通知は、再起動しても二重に出しません。
- 「送信済み」は「引き渡した」だけです。受信は常に「未確認」と表示します。

## バックグラウンド実行

HTTP専用のWindowsタスク（5分ごと。`tools/background_monitor.py http-tick`）が、画像監視のタスク（15分ごと。`tick`）とは別に動きます。登録・解除は画面から別々にできます（[BACKGROUND_MONITORING.md](BACKGROUND_MONITORING.md)）。HTTPのタスクは、Docker・ブラウザ・画像監視を起動しません。停止中・許可切れの監視を再開せず、止まっていた間の検査をまとめて実行することもありません。2026-11-26に実環境で、HTTPのタスクが予定の検査を2回行い、解除まで確認しました。

## 実環境で有効にするまでの手順（USERの承認が必要）

1. 隔離方式の決定と実測（済み：隔離fixtureで18/18 PASS。[HTTP_BOUNDARY.md](HTTP_BOUNDARY.md) の4）。
2. `tools/http_grant.py --data <データ> --site <site id> --trial` で、限定試験の許可に署名する（サイトが1つなら `--site` は省略可）。
3. `HTTP_EXTERNAL_ENABLED = True`（ソース変更。USERの承認のうえで）。限定試験の後は `False` に戻す。
4. 結果を確認してから、通常の許可（`--days 30 --min-interval 300`）に署名し、画面の「HTTP監視を開始」。

## 長期運用

- 履歴は20MiBまで。上限に達する前に監視を止めます（`HISTORY_FULL`）。自動では何も消しません。画面の「履歴を整理」で、履歴を `history-archive/` へ移してから再開できます（削除ではありません）。
- 間隔の2倍を超えて観測がない期間を、画面の「観測がない期間」に表示します。

## 現在の対象外

Webhook送信、IPv6だけのサイト、実サイトでのコンテナの境界の実測、AWS-Bの保存結果の取り込み（従来の別画面のまま）。

## 複数ページ・独自ドメイン

- 1つのサイトに、同じホストのページを最大5つまで（最初のページを含む）登録できます。ページごとに、HTTP監視の設定・許可（署名）・台帳・履歴・通知は別々です。許可は1つのパスにだけ効くので、あるページの許可が別のページに効くことはありません。署名は `tools/http_grant.py --page <page id>` でページごとに行います（「すべてのページ」への署名はありません）。
- 所有権の証拠はサイトのもの（ホストについての記録）で、全ページが共有します。workers.devのサイトはCloudflareのアカウント確認、それ以外のサイトはDNSのTXTレコード（`tools/dns_ownership.py`。利用者が始める別のDNS照会で、承認されるまで無効）で確認します。
