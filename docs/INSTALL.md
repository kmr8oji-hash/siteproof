# 導入・復元・更新・停止・アンインストール

2026-11-25。対象はWindows 11です。**この手順はオフラインで確認したもので、別の新しいPCでの通し確認はしていません（実環境未検証）。**

## 1. 新しいPCへの導入

1. **Python 3.12以降**を https://www.python.org/ から入れます（py launcherを有効に）。確認：`py -0`
2. **OpenSSH クライアント**（Windowsの標準機能）。許可の署名と検証に使います。確認：`ssh-keygen -?`
3. **Docker Desktop**。画像監視の撮影と、HTTP監視の検査（1回ごとの隔離コンテナ）に使います。画面を見るだけなら不要です。
4. SiteProofのフォルダを置き、`SiteProof.cmd` をダブルクリックします。
5. データの保存先を選びます（省略すると `%LOCALAPPDATA%\SiteProof`）。Dockerの制限があるため、**短いパス**を勧めます。

```
SiteProof.cmd --data D:\SiteProofData --remember   … この保存先を覚える（データは移動しません）
SiteProof.cmd --where                               … いま使う保存先を表示する
```

覚えた保存先が見つからないときは、別の空のフォルダで始めず、理由を表示して止まります。

6. 足りないものを確認します（読み取りだけで、起動・取得・登録は何もしません）。画面の「導入環境の確認」でも同じ内容を見られます。

```
py -3.15 -B tools/doctor.py --data <データ>
```

## 2. 固定Dockerイメージの準備

SiteProofは、決まったID（`tools/doctor.py` が表示します）のイメージだけを使い、自分では取得もビルドもしません。イメージがあるPCから移します。

```
docker save <イメージID> -o siteproof-image.tar      （元のPC）
docker load -i siteproof-image.tar                   （新しいPC）
docker image inspect --format "{{.Id}}" <イメージID>  → doctor.py が表示するIDと一致すること
```

- **この移行は未実測です。** Docker Desktopのイメージ保存方式（containerd イメージストアか従来方式か）が違うと、IDが変わる可能性があります。IDが違えば、SiteProofは使わずに止まります。
- `runtime/docker/Dockerfile` からの作り直しは、aptのパッケージが固定されていないため、**同じIDになるとは限りません**。IDが変わる場合は、撮影構成の見直しと、許可の署名のやり直しが必要です。

## 3. バックアップと復元

```
py -3.15 -B tools/backup_data.py --data <データ> --dest <保存先>
py -3.15 -B tools/restore_backup.py --backup <バックアップ> --dest <新しいフォルダ>
```

- 復元は必ず**新しいフォルダ**に行います。既存のデータには上書きしません。照合に合格したバックアップだけを復元します。
- 復元した側の監視とメールは、**すべて停止した状態**になります（理由：復元したデータ）。必要なものだけ、画面から開始します。
- 許可と回数の記録もそのまま写ります。元と復元先を**同時に使わないでください**（回数の記録が食い違います）。
- 署名鍵（`~/.ssh`）とメールの資格情報（資格情報マネージャー）は、バックアップに含まれません。

## 4. 更新（プログラムの入れ替え）

1. 画面で監視を停止し、SiteProofを閉じます。
2. `py -3.15 -B tools/pre_update.py --data <データ>`（環境の確認と、照合つきバックアップ）
3. プログラムのフォルダを入れ替えます。データフォルダは別の場所なので、そのまま使えます。
4. `SiteProof.cmd` を起動し、`tools/doctor.py` を確認します。戻すときは、以前のプログラムのフォルダに戻します。
5. Pythonやフォルダの場所が変わったら、Windowsタスクを登録し直します。

`src/noxiworks/permit.py` など撮影構成として署名に固定されたファイルが変わる更新では、**画像監視の許可の署名し直し**が必要です（Sprint 03の更新が該当します）。RC1（2026-11-26）の更新は、固定されたファイルと撮影バンドルを変えていないため、署名し直しは不要です。

## 5. 監視の停止

| 止めたいもの | 方法 |
|---|---|
| 1ページの画像監視・HTTP監視 | そのページの画面の停止ボタン（別々に止まります） |
| サイト全体 | 「このサイトの監視をすべて停止」 |
| アプリを閉じている間の監視 | 画像・HTTPそれぞれの「解除」 |
| タスクの確認 | `py -3.15 -B tools/background_monitor.py status --data <データ>` |

停止した監視は、自動では再開しません。

## 6. アンインストール（データを残す）

```
py -3.15 -B tools/uninstall_check.py --data <データ>
```

プログラムの外にあるもの（Windowsタスク・データ・バックアップ・保存先の設定）と、使えるコマンドを一覧にします。**このツールは何も削除しません。**

1. Windowsタスクを解除します（上の表）。
2. プログラムのフォルダを削除します。データフォルダとバックアップはそのまま残ります。
3. 署名鍵（`~/.ssh/siteproof_permit`）と資格情報マネージャーの `SiteProof-SMTP-…` は、あなたのものです。不要なら自分で削除します。
4. Dockerのイメージやvolumeも、SiteProofは削除しません。

## 7. 日本語を含むパス

データフォルダやPythonのパスに日本語があっても、バックグラウンド用のファイルを作れるようにしました（UTF-8で書き、`chcp 65001` を使います）。生成したファイルを実際に `cmd.exe` で動かして確認しています。**Windowsのタスク スケジューラからの実行と、日本語パスでのDockerの撮影は未検証です。**
